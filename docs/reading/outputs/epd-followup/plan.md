# EPD后续：先用已有证据定位退化，再决定新实验

第一轮复现已完成，旧交付目录及ZIP保持封存；本目录记录用户“继续工作”后的独立分析批次，不改变第一轮审批或统计结果。

## 本批次目标与成功标准

对最终选用的双H20数据做CPU离线分析，回答哪些时延现象已有证据、哪些仍需GPU profiling才能判断。形成可审查的下一阶段实验方案；新模型、负载或基线设定按AGENTS先独立审查再交用户确认。

1. **确认来源。** 从封存summary的source_case选择16个H20配置，共4800正式请求；首1图/C1只用cache-fix，其余用原矩阵。核对源文件SHA与最终交付清单，记录逐文件来源；只读、不改写旧材料。
2. **校正事件语义。** 查看固定官方EPD源码，确认各lifetime event记录位置、时钟、重复事件与覆盖行为，尤其不能把最后一次decoding_begin/end误作整个128-token解码阶段。独立列出事件覆盖、有限值和时序异常；异步CPU提交跨度不能解释成GPU通信完成耗时。
3. **量化可观测时延。** 每配置从原请求重算TTFT、128个token的127个间隔与首末token窗口、E2E及可用的编码/预填充/迁移接口跨度；输出P50/P95和每次重复。比较同case基线/EPD时仅比较同一时钟域定义；不对相互重叠的跨度硬求和，不将分位数相加作总分位数。
4. **提出最小后续实验。** 针对观察到的差异制定有明确证伪条件的profiling方案，优先保持模型/输入/输出/原基线预算不变。PD仅做源码可行性与资源预算方案，先明确E归属、P/D数量、设备共享和路由，不能以两卡PD宣称胜过三卡EPD。

验收：来源4800条覆盖完整；脚本自身校验与独立少量手算一致；报告分清“原始观察、源码支持、尚未证实的因果假设”；G4审查分析结论，G5审查本批次交付。下一轮实验只形成方案，不在本批次启动GPU作业。

## G1批准后落实的分析约定

Claude G1为APPROVE_WITH_NITS、BLOCKING为0（reviews/g1-followup-offline.md）。仅批准离线批次；GPU profiling、PD/DistServe实际搭建仍须另行具体审查及用户确认。

- 源码来自本地官方Git bundle的完整commit `9b111f710dfb4724072b603d626a1e4dad93ef1f`，不需SSH。导出相关文件后对分析副本应用归档的H20最终合并补丁；逐文件上游/重放SHA另存source/replay-manifest.json，不执行这份源码。基线原始和缓存修正版实际快照的generate函数做AST对照，核对时间戳路径。
- G3明确为“事件语义及隔离CPU复现的证据审查”，在G4使用事件跨度前完成；不是新增GPU通信预检。对设计上P先产生token、迭代覆盖和重复追加三种解释分别核对源码；数据检查decoding_begin更靠近第二还是最后token。
- 首间隔单列；后126个间隔给P50/P95/P99/max，并保留各重复。基线只有token时间戳，不能与EPD单阶段事件跨度跨系统比较。两套打点都属于服务输出通知观察，具体callback不同；不是GPU kernel完成时间。
- 先登记四种假设：单D资源/批量效率（生成窗口重叠数及间隔随并发变化）；每步固定开销（C1后续间隔整体差异）；交接延迟（差异集中首间隔）；E/P等待（TTFT各事件间隙随负载变化）。离线只能支持或排除部分现象，不能据相关性证明因果。输出窗口重叠数按端点与首末token时间重建，不冒充实际GPU batch size。
- 重算TTFT/TPOT/E2E P50/P95与封存摘要逐配置对账，偏差作为发现且不覆盖旧值。分析前后对旧目录全部清单文件及外层ZIP重新算SHA。两host分开；排除预热、sapphire诊断和旧被替代请求。跨负载趋势注明C1来自后补会话；P95每300条约15尾样本，附各100条重复统计。
- 新实验建议逐项写明是否改用户固定设置、profiling扰动控制、相同请求/RGB缓存条件、三卡预算及空闲卡检查，不把书面方案批准当实验启动授权。
