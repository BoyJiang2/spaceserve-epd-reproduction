# 本轮复现结论

SpaceServe完整矩阵的技术复算通过：qjh000同一张H20，Qwen2-VL-7B FP16/TP1/eager，18配置、5400正式＋360预热，正式失败率0，全部输出128 tokens。全量数据及报告独立G4均APPROVE_WITH_NITS、BLOCKING0；G5也已APPROVE_WITH_NITS、BLOCKING0；最终封包完整性以目录外integrity记录为准，当前状态见[验收索引](acceptance-checklist.md)及[status](../status.json)。

本轮没有普遍吞吐收益。未划分SpaceServe的吞吐相对原生范围为−6.32%至＋5.86%；启用编码器SM掩码后相对原生为−7.52%至＋6.29%。SM掩码在新增四个负载点均降低吞吐。比值是三重复均值之比，未做显著性检验。

原生所有进程采样峰值为60.631–62.211GiB，解耦组为63.178–63.650GiB，掩码组为63.178–63.721GiB；没有OOM。采样峰值不是瞬时精确峰值。Space主模型仍保留visual权重，另驻留675,759,104参数的encoder，因此不能将额外视觉权重从预算中剔除。

官方fork经最小兼容补丁后，在本环境已证明同GPU实际FP16驻留、编码与语言CUDA执行重叠、cold/restart共90固定案例，以及实际encoder stream的SM掩码78→64、零掩码恢复78、重施和首次真实编码64。掩码仅限制encoder stream，不是decoder互斥分区或完整论文SIS；机制生效不等于吞吐提高。

实际图片序/RGB与processed input IDs一致，输出ID差异按配对完整保存：含预热配对的不同数量为0–96/320，正式请求配对为0–90/300；固定案例通过不能推导全部性能请求逐token或语义一致。差异来源尚未确定。没有用FP16作未经验证的归因。

本批组别按固定顺序执行，未随机交错；未独立排除时间漂移及所有瞬时外来负载。吞吐/时延差本身不能唯一归因为通信、CPU调度、GPU计算或SM限制。正式测量关闭profiler，预检trace重叠比例不用于推导正式利用率。固定并发三重复也不提供真实到达率SLO结论。

EPD方案A使用qjh003的MiniCPM-V-2_6、同三张H20，对照三个完整副本；2400正式＋160预热未重跑，已受限G4/G5封存。关闭观测时低/高吞吐为三副本的0.930/0.941倍，均无加速。高负载EPD观测扰动5.0027158%越过5%诊断阈值，高EPD trace只证明路径存在；未执行缩窗重采，不称原重采门槛通过，也未确定off运行的因果瓶颈。见[EPD报告](../../epd-profile-a/report/report.md)。

旧4090/L20的2B、qjh003的三卡EPD、qjh000的单卡7B分别与各自同机基线比较，不拼成跨模型/硬件绝对排名。旧三个封存目录与固定ZIP已逐成员绑定校验，原失败和首旧采样失败300＋20完整保留且未入选。

建议下一轮优先做保持模型和GPU预算的交错复测，检验时间漂移、批处理与阶段服务率，再按明确假设选择最小消融。现有数据不足以支持直接扩大模型、自动资源搜索或预设论文A100加速倍数。本轮未新增PD/DistServe或跨机拆分。
